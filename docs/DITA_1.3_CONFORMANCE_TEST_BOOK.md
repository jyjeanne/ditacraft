## 1. Purpose and scope

This test book shows, requirement by requirement, how the DitaCraft language server applies the DITA 1.3 standard, and which tests demonstrate it. For each requirement it gives the text of the standard (or the other source of the rule), what the language server does, the tests that prove it, and a status.

**In scope**: the language server (`server/src`): validation (13 phases), addressing and content references, keys and key scopes, subject schemes, DITAVAL files, and the editing features it provides (completion, navigation, rename, formatting…). Where a DITA behaviour is implemented by the extension rather than the server (DITAVAL filtering in the editor, grammars and catalogs), its tests are cited as evidence.

**Out of scope**: publishing (done by DITA-OT), the user interface of the extension (see the manual test plan), and DITA 2.0 conformance beyond the version gating of rules.

The language server is a DITA-aware *editing* processor (§4.3, "Editing, managing, and storage"). It does not produce output: it checks the addresses, references, keys and controlled values that a publishing processor will resolve, and it reports what would fail or mislead.

## 2. Method

### 2.1 Sources of requirements

| Source | Meaning |
|---|---|
| DITA 1.3 §x.y | Normative text of the OASIS standard, quoted from the edition above. |
| DITA-OT `CODE` | Behaviour of the reference processor DITA-OT 4.3.5, from its message catalog (for example `DOTX010E`). Used where the standard leaves the behaviour to processors. |
| Grammar | Content models of the OASIS DTD and RELAX NG grammars. |
| Best practice | Schematron-equivalent or editorial rule; not required by the standard. |
| Tool | Behaviour of the editor that the standard does not cover (security, workspace, performance). |

### 2.2 Status

| Status | Meaning |
|---|---|
| ✅ Verified | At least one automated test asserts the required behaviour precisely. |
| 🟡 Partial | Tested, but only part of the requirement, or with assertions that would not catch every regression. The note says what is missing. |
| ❌ Not tested | No automated test demonstrates the requirement. The note says whether it is implemented. |
| ⚠️ Deviation | The language server does not behave as the source requires. Each deviation was reproduced on the code baseline; see section 7. |
| ☑️ Accepted | The language server is deliberately stricter than the source, as a best-practice check, by a decision of the action plan. The note says why. |
| ➖ Out of scope | A feature of the standard that the language server does not provide, by a decision of the action plan. The conformance statement lists it. |

### 2.3 Types of tests

| Type | Where | How it runs |
|---|---|---|
| Server unit and integration tests | `server/test/*.test.ts` | Plain Mocha, no VS Code. In-memory documents, or files written to a temporary workspace with a real key space and subject scheme service. |
| Editor core tests | `src/test/shared/*.test.ts` | Plain Mocha: grammars, catalogs, preview, DITAVAL in the preview and visual editor. |
| Client integration tests | `src/test/suite/*.test.ts` | Inside a VS Code instance, with the real language server. |
| MCP server tests | `mcp/test/**/*.test.ts` | The MCP server, which runs the same validation pipeline, with real DTD validation and catalogs. |
| Corpus tests (opt-in) | `server/test/docsDataset.test.ts` | The whole DITA-OT documentation (about 300 topics); only when `DITACRAFT_DOCS_DATASET` is set. |
| Manual tests | [MANUAL_TEST_PLAN.md](MANUAL_TEST_PLAN.md) | By hand in VS Code. |

### 2.4 Running the tests

| Suite | Command |
|---|---|
| Language server | `cd server && npm test` (one area: `npm test -- --grep "validateCrossReferences"`) |
| Language server with coverage | `cd server && npm run coverage` (gate: 90% lines, statements and functions, 80% branches) |
| Editor core | `npm run test:shared` |
| MCP server | `npm run compile && npm run test:mcp` |
| Client (VS Code) | `npm test` |
| DITA-OT documentation corpus | `cd server && DITACRAFT_DOCS_DATASET=<dita-ot>/docsrc npm test` |

Every test cited below is linked to its file and line in the code baseline.

- **KEY-07** ([DITA 1.3 §2.3.4.1](https://docs.oasis-open.org/dita/dita/v1.3/errata02/os/complete/part3-all-inclusive/archSpec/base/keys-core-concepts.html)): Accepted deviation (decision D3 of the action plan): stricter than the specification on purpose. ## 9. Conformance statement (proposed)

DITA 1.3 §4.1 requires that "Conforming DITA implementations MUST include a conformance statement that gives the version of the DITA specification that is supported." The project does not publish one yet. Proposed wording, to adopt in the README once the deviations of section 7 are fixed or accepted:

> The DitaCraft language server is a DITA-aware editing processor that supports DITA 1.3 (OASIS Standard, Errata 02), as well as DITA 1.0–1.2 and 2.0 documents. It validates documents against the OASIS grammars and checks URI-based and key-based addressing, content references, key scopes, subject scheme controlled values and DITAVAL files. It does not produce output, and it does not apply branch filtering (`<ditavalref>`). Known deviations from DITA 1.3 are listed in the DITA 1.3 conformance test book.
